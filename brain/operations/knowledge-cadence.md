# Event-driven updates

Update the brain when a durable fact changes: product behavior, pricing, positioning, team membership, social identity, current goal, public proof, partner relationship, event outcome, publication policy, or brand system.

# Suggested rhythm

- **After an event or customer conversation:** capture facts, quotes, outcomes, and gaps as a proposal.
- **Weekly:** review the current goal, stale concepts, unresolved public claims, and newly generated research.
- **Monthly:** review product capability truth, commercial claims, social destinations, proof, and ownership.
- **Before every public campaign:** validate the bundle and re-check all time-sensitive external facts.

# Ownership

Replace broad `team:*` placeholders with real accountable owners as the company directory is established. An owner is responsible for accuracy and review, not necessarily authorship.

# Change protocol

1. Edit the smallest durable concept.
2. Preserve or add sources.
3. Update lifecycle, freshness, and publication metadata.
4. Update the nearest index when structure changes.
5. Add a concise entry to `/log.md`.
6. Run `make validate`.
7. Review the Git diff before merging.
