# Deterministic Rules Engine (DRE)

The **Deterministic Rules Engine (DRE)** represents the foundational safety and compliance layer for the Allegro customer-support bot. Its main purpose is to deterministically generate robust System Prompts by merging non-overridable **Core Rules** with tenant-specific **User Rules**.

By structuring the prompt in a rigorous and predictable manner, the DRE ensures that critical safety rules (such as refusing to negotiate prices or withholding PII) are strictly adhered to by the LLM and are protected against prompt injection attacks from users.

## Architecture

The module is located in `backend/src/dre/` and consists of two main components:

1. **`rules.py`**: Defines the `DEFAULT_CORE_RULES` (e.g., no price negotiation, never share PII) and strict prompt text templates (`PREAMBLE`, `CORE_SECTION_HEADER`, etc.) that govern how the final prompt is structured.
2. **`engine.py`**: Exposes the `DeterministicRulesEngine` class. This class is responsible for assembling the core rules and user rules into the final, coherent system prompt injected into the LLM.

### Rule Hierarchy

1. **Core Rules**: These are mandatory, structural rules governing bot behavior across the board. They are always placed at the top of the generated prompt under a strict warning header.
2. **User Rules**: These are configurable instructions that change based on the specific tenant (e.g., "Always greet the customer in Polish"). They are appended below the core rules to ensure they can never override the mandatory directives.

## Usage

Using the engine is straightforward. You instantiate the `DeterministicRulesEngine` and then build the prompt for a specific interaction by passing in the user's rules.

```python
from dre.engine import DeterministicRulesEngine

# Instantiate the engine. It defaults to using DEFAULT_CORE_RULES from rules.py.
# You can also pass custom core_rules if needed.
engine = DeterministicRulesEngine()

# Provide tenant-specific user rules
user_rules = [
    "Always greet the customer in Polish.",
    "If the customer asks about shipping times, suggest checking the FAQ."
]

# Build the final system prompt block
system_prompt = engine.build_system_prompt(user_rules=user_rules)
```

The resulting `system_prompt` can then be used directly as the `{"role": "system", "content": system_prompt}` message when calling the LLM.

## Evaluation Suite

The DRE comes with a comprehensive evaluation suite located in `backend/src/dre/evals/`. It includes both deterministic unit checks and empirical LLM-as-a-judge tests to ensure the generated prompts effectively restrict LLM behaviors.

### 1. Deterministic Evals
Validates the mechanical creation of the prompt. It uses cases defined in `evals/cases/dre_golden_cases.json` to ensure substrings (like specific rules and section headers) appear correctly and in the correct order.

**Run the deterministic evals:**
```bash
python3 src/dre/evals/evaluate_dre.py
```

### 2. LLM Evals (Adversarial Testing)
This suite tests how the LLM actually responds to the prompt generated by the DRE. It uses adversarial prompts defined in `evals/cases/dre_llm_cases.json` (e.g., aggressive customers, prompt injections) and evaluates the LLM's response using an **LLM Judge** (`src/dre/evals/judge.py`).

**Run the LLM evals:**
*(Requires your virtual environment to be activated and `OPENAI_API_KEY` to be set)*
```bash
PYTHONPATH=src python3 src/dre/evals/evaluate_dre_llm.py
```

You can optionally specify a different model or judge model:
```bash
PYTHONPATH=src python3 src/dre/evals/evaluate_dre_llm.py --model gpt-4o --judge-model gpt-4o
```
